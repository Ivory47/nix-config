# CLAUDE.md — notifications (moved from the root CLAUDE.md; original section 13)

## 13. Notifications (`notifications/`, config `qs -c notifications`, added 2026-11-18, branch `feature/notifications`)
Replaces **mako** (removed from `gui/applications/default.nix`; it had no config file, so it drew its built-in blue box). This process owns the D-Bus name `org.freedesktop.Notifications` (Quickshell's `NotificationServer`, `Quickshell.Services.Notifications`): **while it is not running, senders get an error and nothing is shown** (`qsr` has a moment like that). It is started by `hyprland.lua` and `reload.sh`. While mako (or another server) still holds the name, this one gets none: stop it first (`kill` its PID; D-Bus can re-activate it only while its service file is installed, i.e. before `hms` has removed the package).
- Files: `shell.qml` (the server, `IpcHandler` target `notifications`: `dismissAll`, `count`), `NotificationPopups.qml` (the window and the list), `NotificationCard.qml` (one notification).
- **Window:** one transparent `PanelWindow` on the Overlay layer, anchored top, right and bottom, 380 px wide, with the top margin `Theme.statusBarHeight + spacing`; `mask: Region { item: column }`, so only the cards take the mouse. Its screen is the focused monitor's, picked only while no card is showing (a window that changes screen is recreated, which must not happen under a card's glass). Newest on top, at most 4 shown (`maxShown`), the others wait (their time does not run); a card pushed out by newer ones comes back when there is room.
- **Card:** the glass is a `LucentGlassPanel` (`PanelGlassStyle`, corner radius `Theme.radiusLarge`, blur `Theme.glassBlurRadius`) that is a child of the window's top item, NOT of the card, with x, y, width and height bound to what the card draws (card slot + slide offset; its opacity follows `appear`). Same reason as the overlay's neighbours (section 12): the plugin takes a glass's region from the item's own position and size and only hears of changes to those. Without the plugin or with `Theme.glass` / `Theme.compositorGlass` off: an opaque `Theme.background` panel (checked). The border is the bar's (`barBorderColor` at `barBorderOpacity`), red and 2 px for a critical notification. Content: the image, else the app icon (`Quickshell.iconPath(name, true)`; an absolute path is used as it is), else a bell on a tile; app name and time (the close button while the mouse is over it); the summary (plain text, bold, 2 lines); the body (3 lines, `StyledText`, so `<b>`, `<i>`, `<u>` work; links are off); the actions as outline chips (the `default` action has no chip: it is what a click on the card runs); a thin line that shows the time left.
- **Time:** `Theme.notificationTimeout` seconds (Settings > Notifications, default 5, 0 = until clicked away), 1.6 times that for a notification with actions, the sender's own timeout when it gives one (**`Notification.expireTimeout` is in MILLISECONDS although Quickshell's docs say seconds**: checked with `-t 2000`), never for a critical one. A timeout of 0 or -1 both mean "use the default": the spec says 0 is "never", but a sender that wants that should send critical urgency (this was chosen because the Claude Code notifications, which stayed until clicked under mako, may be sending 0: see below). Paused while the mouse is over the card (`HoverHandler`). A replacing notification (same id, `notify-send -r`) updates the card in place and restarts its time. A click runs the `default` action, else dismisses (close reason "dismissed"); an action chip invokes the action and then dismisses unless the notification is `resident`; expiry is reason "expired".
- **Life of a card:** the `Notification` object is kept by a `RetainableLock` until the card has faded out and its slot has collapsed, so the card can still show it while it goes (Quickshell destroys a notification right after `closed`). The slot (`NotificationCard` is the Column's item, `height = (card + gap) * collapse`, `clip: true`) collapses as the card fades, so the cards below slide up.
- **Testing without touching mako:** run the scratch copy on a private session bus, which has its own free name: `dbus-run-session -- script`, where the script starts `qs -p <scratch>/n` and sends with `busctl --user call -- org.freedesktop.Notifications /org/freedesktop/Notifications org.freedesktop.Notifications Notify 'susssasa{sv}i' app replaces_id icon summary body <n actions: N a1 t1 ...> <n hints: N key type value ...> timeout` (`--` is needed for a timeout of -1; urgency: `1 urgency y 2`). `notify-send` is not installed. The layer surface shows on the real screen, `grim -g "1000,0 440x300"` takes it. `busctl --user monitor --match "type='signal',interface='org.freedesktop.Notifications'"` on the same bus shows `ActionInvoked` / `NotificationClosed` (with the reason). QtTest `TestCase.mouseClick(item, x, y)` / `mouseMove` inside the scratch (a test-only IPC hook that is not in the repo) clicked the card, the chip and the close button.
- **Checked** (scratch copy, private bus, live session with the plugin): the look with glass (terminal text behind is a smear), a plain one, a long body (3 lines, elided), actions, critical (red border, stays), 5 at once (4 shown, the oldest waits), bell tile and a named icon, replace in place (the time line restarts), expiry (default 5 s, 8 s with actions, `-t 2000`), hover pause and release, a click on the card (default action, then closed with reason 2), the close button (reason 2), an action chip (`ActionInvoked` then closed), the no-plugin / `compositorGlass: false` fallback, no QML warnings. NOT checked: the real Claude Code notifications (a monitor on the real bus logs the real `Notify` calls to see what timeout it sends), an image from `image-data` (the card passes `image` through), several monitors and the screen switch, real mouse use, a notification while a fullscreen window is open, many in a row, the settings page entry, the start through Hyprland, taking the name from mako.

**Drop shadow and test button (2026-11-18).** The cards have a drop shadow (`Theme.notificationShadow.opacity/blur/offset`, Settings > Notifications; the same values for the bar's notification centre, `status-bar/BarPill.shadow`). It is a `GlassShadow` (it takes `strength/softness/drop`, defaults the popups' values) in an Item in the window's top item with `z: -1`, bound to the glass's geometry like the glass itself. The window is wider than the cards (`shadowRoom` on the left, cards inset `spacingMedium` from the right edge) and starts right under the bar, so the shadow is not cut off; the bar windows got `shadowRoom` extra height for the same reason. Settings > Notifications has a "Test notification" button (`ThemePage.actions.testNotification`: `busctl --user call -- ... Notify`; the `--` is needed for the timeout -1). Checked in scratch copies (cards with opacity 0 and 0.6 side by side, the balanced bar's panel, search for "status bar" / "notifications"); NOT checked: the button itself (no clicks), islands/notch panels' shadow, the shadow of a card falling on the card below it.
