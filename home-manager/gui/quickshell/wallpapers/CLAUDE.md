# CLAUDE.md — wallpaper picker (moved from the root CLAUDE.md; original section 12)

## 12. The wallpaper picker (`wallpapers/`, config `qs -c wallpapers`)
A **normal window** (Quickshell `FloatingWindow`, title `Wallpapers`, class `org.quickshell`) with the compositor's glass behind it (`LucentListPanel` filling the window; guide: `shared/glass/GLASS-WINDOWS.md`). No captured glass, no `GlassBackdrop`/`GlassTag`, no Hyprland blur (the plugin turns it off for a window with glass), no shadow of its own (Hyprland draws the border and the shadow). There is deliberately **no window rule**: it opens as a normal tiled window like any other (it asks for 1120x700, which matters only if you float it yourself); do not add `float`/`size`/`center` rules for it unless the user asks. Glass corner radius 6 = `decoration.rounding`. Open/close with `shown` (the window exists only while it is true: `visible: shown`; toggling it was checked repeatedly, no crash, unlike the captured glass in section 9); closing the window from the compositor (Super+C) sets `shown` false through `onClosed`. It does not close on a workspace change and has no exclusive keyboard focus (a normal window: Hyprland focuses it when it opens, and the search field is focused again after 80 ms). Without the plugin, or with `Theme.glass`/`Theme.compositorGlass` off, it is an opaque `Theme.background` panel with plain highlights (checked). Opened with Super+W (`hyprland.lua`), the desktop entry "Wallpapers" (`default.nix`: `quickshell-wallpapers-toggle` script that toggles over IPC, or starts the shell and shows it when it is not running), or `qs -c wallpapers ipc call wallpapers toggle|show|hide|isOpen`. Started at login by `hyprland.lua` and by `reload.sh`.
- Files: `WallpaperPicker.qml` (window, panel, keys, apply), `WallpaperModel.qml` (`FolderListModel` of `~/Pictures/Wallpapers`, search/filter, `awww query` for the current one), `WallpaperStore.qml` (tags and the colour/scheme/mode choice per wallpaper), `ColorCache.qml` (all matugen calls), `WallpaperCard.qml`, `DetailPane.qml`, `TagChip.qml`.
- Data outside the store: `~/.config/quickshell-wallpapers/wallpapers.json` (`{tags: {file: [..]}, choice: {file: {index, type, mode}}}`, keyed by file name, so renaming a file loses its tags) and the cache `~/.cache/quickshell-wallpapers/colors.json` (source colours per file, keyed by name + mtime). Both honour `XDG_CONFIG_HOME` / `XDG_CACHE_HOME`.
- matugen: source colours from `matugen image <f> --show-source-colors` (one process at a time, selected wallpaper first, the rest prefetched while open, about 0.25 s each); the live scheme preview from `matugen color hex <c> -t <type> -m <mode> --dry-run -j hex -q` (reads `colors.<role>.default.color`). **Apply** (button: stays open; Enter or double-click: closes on success) runs `awww img -a <f> && matugen image <f> --source-color-index <i> -t <type> -m <mode>`; matugen's own config (templates, kitty hook) does the rest. **The kitty hook** (`matugen/config.toml`) is `kitty @ --to unix:/tmp/kitty-socket set-colors --all --configured ~/.config/kitty/colors.conf`: `--all` recolours the windows that are open, `--configured` also changes what NEW windows get (without it a window opened later with Super+Q, which asks the headless instance `HeadlessKitty` over its socket for a new OS window, kept the colours of the time that instance started; reproduced and fixed in a throwaway kitty instance with its own socket: configured colours stayed old with the old command and followed with `--configured`), and `--to` makes it work when the shell was started by Hyprland (no terminal, no `KITTY_LISTEN_ON`: plain `kitty @` fails with "open /dev/tty"; it only worked while the shell had been started from a kitty window with `qsr`, which inherits the variable). The config file is deployed by `hms`, so the fix needs it. Errors from either tool are shown under the button and the popup stays open. Nothing is applied while browsing.
- Keys (typed in the search field): arrows move in the grid (so Left/Right do not move the text cursor), PageUp/Down, Enter apply+close, Alt+1..5 colour, Alt+Left/Right scheme type, Alt+M light/dark, Ctrl+T tag field (Esc comes back), Esc clears search and tag filters, then closes, Ctrl+C closes. Search: all words must match; a word matches a part of the file name or of a tag, `#word` the start of a tag; the chips under the search field are tag filters (all must match).
- The selected and hovered card are highlighted by the glass (`LucentListPanel.hlRect1/2`, with the `GridView`); the card, field and rest of the content are transparent where the highlight is, as in section 9. (The strict "nothing translucent over the glass" rule of section 9 is for the captured glass only; the content is opaque anyway.) `LucentListPanel` re-reads a card's own x/y so that the highlight follows the grid when the window is resized; the grid also scrolls to the current wallpaper again when its height or cell width changes, until the user has chosen one.
- Checked as a window (scratch copy of the deployed config with the new files, `qs -p`, in the live session with the user's loaded plugin, 1440x810 logical): with a temporary live rule (`hyprctl eval`, not saved) the window floated at 1120x700 and centred, glass behind it (the wallpaper and the terminals behind are blurred), thumbnails, selection highlight on the current wallpaper, tags/colours display, repeated open/close and a compositor-side close (no crash report), the no-glass fallback. NOT rechecked as a window: apply, keyboard, tags (no keys were injected; the code is unchanged), mouse hover/click, resizing by hand, a tiled window (it opened tiled before the temporary rule and showed the glass, but only a small tile was looked at), a second monitor.
- Earlier checks as a layer popup (scratch copy of the deployed launcher config with the new files, `qs -p`, `XDG_CONFIG_HOME`/`XDG_CACHE_HOME` pointed at a scratch dir, laptop 1920x1080 at 1.333, plugin's glass): layout and screenshots, thumbnails, colour dots and cache file, search, the selection starting on the current wallpaper, tags added by keyboard and written to the JSON, Alt+2 / Alt+Right / Alt+M (choice saved), apply with logging stubs for `awww`/`matugen` (exact commands, popup closes) and with a failing stub (error shown, popup stays), no QML warnings, no crash report. Built with `nix build` from the flake: the `wallpapers` config derivation, the toggle script and the icon.
- NOT checked: `#tag` search and the tag filter chips, the two-step Esc, mouse (clicks, double-click, hovering, the chip ×, the colour swatches), a real apply (awww transition, kitty/Hyprland colours), the desktop entry from the real launcher, Super+W, a cold start through the toggle script, light mode on the glass beyond the preview, wallpapers dropped into the folder while open, many (hundreds of) wallpapers (thumbnails are decoded at cell size, asynchronously, but the grid is not paged), the captured-glass fallback (no plugin).
- Testing note: `qs -p <dir> ipc call wallpapers show` only prints the IPC listing: use `toggle`/`hide`. Injecting keys with `wtype` while a scratch popup is open once sent an Escape to the Claude Code terminal (the popup did not hold the keyboard at that moment, cause unknown), which interrupted the session. Check `isOpen` first and close with IPC `hide` rather than Escape.

**The overlay form (`wallpapers/WallpaperOverlay.qml`, branch `feature/wallpaper-overlay`, 2026-11-18).** The same picker as a full-screen layer-shell overlay (namespace `wallpapers-overlay`, plain `PanelWindow`: no `GlassPopup`, no glass, no capture; the desktop is dimmed only 22%, `WallpaperOverlay.dim`). The selected wallpaper is shown at half the screen's width and height in the middle, with the neighbours smaller on both sides, almost as opaque as the middle one (92% at the first neighbour, fading out towards the edges) but less saturated and flatter (`sideSaturation` -0.35, `sideContrast` -0.2, a `QtQuick.Effects` `MultiEffect` per picture whose strength follows the distance from the middle; the `Image` itself is hidden) so that the middle one stays the centre of attention; only the pictures within 3 positions load an image. The filter bar at the top and the key hints at the bottom sit on dark plates (`plateColor`, black 82%) so that they read over any window on the desktop; the filter bar is a segmented control (a slim plate with 4 px of padding, chips that fill its height, the chosen one solid in the accent colour, the others without an outline, the count in a dimmer colour; its own delegate in `WallpaperOverlay.qml`, not `TagChip`, which is for tags on pictures and in the window). **The neighbours have compositor glass behind them** (2026-11-18): a `LucentGlass` (`Glass.Native`) per picture, blur `sideBlur` (7, sigma in logical px), `sideGlass` turns it off, so what shows through their translucent pictures is the desktop blurred, not sharp (checked by A/B in a scratch copy in the live session: terminal text behind a neighbour is an unreadable smear with the glass and sharp without it, i.e. with `Theme.compositorGlass` off; no stray rectangles mid-glide; it also needs `Theme.glass`, the plugin and a layer-surface-capable build, and does nothing otherwise). Two facts about `LucentGlass` that shaped it: the region it sends is its OWN scene position and its own width/height (it ignores the scale of an ancestor) and it is only updated when its own geometry or visibility changes (not when an ancestor moves or scales), so the glass is NOT a child of the scaled, animated card but sits in the unscaled `stage` with x, y, width and height bound to the card's drawn rectangle (`card.x + card.width * (1 - card.scale) / 2` and so on), which changes at every step of the glide; its `glassOpacity` follows the card's opacity so that it fades out with it, its corner radius is the card's scaled one, and it is off under the middle picture (opaque) and while a card is nearly in the middle (`card.a` below 0.15). These looks are properties at the top of the picture section of `WallpaperOverlay.qml`; the file name, "n / total", the scheme type and mode, and the matugen source colours are an overlay on the bottom of the middle picture (name left, swatches right). **Scrolling**: wheel / touchpad (deltas add up, 120 per step, down or right = next), Left / Right (or H / L), Home / End, a click on a neighbour; **colours**: click a swatch, **Shift+Left / Shift+Right** (previous / next, wraps round; chosen because plain Left / Right already scroll and Shift is the usual "other axis" modifier; Ctrl+arrows may be used by the compositor or terminals), keys 1 to 5, Up / Down (also cycle); Esc, Ctrl+C or a click outside the pictures close it, Enter applies the one in the middle (if it is not applied yet) and closes, Space only applies; it also closes on a workspace change. **Applying is immediate** in the sense that a wallpaper is applied once the selection has rested 320 ms (so a fast scroll applies only where it stops), and a colour 120 ms after the click: `awww img -a <f> && matugen image <f> --source-color-index <i> -t <type> -m <mode>` for a new wallpaper, only the `matugen` part for a new colour of the applied one. One job runs at a time and only the latest request waits behind it; scrolling back to the wallpaper that is already applied cancels a waiting job; the scheme type and mode are the ones saved for that wallpaper (`WallpaperStore`, set in the window form) and the colour picked here is saved too. A failure of either tool is shown in red under the name. It starts on the wallpaper that is on the screen (`awww query`). **IPC** (now in `wallpapers/shell.qml`, `WallpaperPicker` no longer has its own handler): `toggle` / `show` = the window (unchanged), `toggleOverlay` / `showOverlay` = the overlay, `hide` = both, `isOpen` = either; opening one closes the other. **Opening it:** **Super+W opens the overlay** (`hyprland.lua`); the window form has NO keybind any more (the earlier Super+W and Super+Shift+W binds were removed on request): it is the `window` action of the Wallpapers entry in the app launcher (the Overlay | Window toggle, section 9), or `qs -c wallpapers ipc call wallpapers toggle`. The desktop entry: its `exec` is `quickshell-wallpapers-toggle overlay` and the `window` action `... window`, so by the launcher convention (section 9) the launcher shows an Overlay | Window toggle and the DEFAULT of the entry is now the overlay. The toggle script's cold-start path (shell not running) used `ipc call ... show`, which only prints the IPC listing here and never opened anything; it now waits for `isOpen` to answer and then toggles (checked with a fake `qs`, cold and warm, both modes). Checked (scratch copy of the deployed config with the working tree's files, logging `awww`/`matugen` stubs, a test-only IPC hook that was not kept for stepping, picking and feeding wheel deltas; live session, 1440x810): the layout and its look at the current and a mid-list wallpaper, several quick steps apply only the last wallpaper, a colour pick runs only matugen with the right index, stepping away and back applies nothing, wheel notches and half-notches, the saved choice, a failing `awww` (error shown, cleared by the next good apply), the window form and `hide` through the new IPC, no warnings, no crash report. NOT checked: real wheel / touchpad events and their direction and speed (only deltas fed through the hook), the keys, clicks on swatches or neighbours, a real apply (awww transition, kitty and Hyprland colours: `matugen` reloads on every colour change, which may be heavy when scrolling fast), other screen sizes or several monitors, a very large wallpaper folder, and the overlay while the window form's data changes at the same time.

**Escape and Ctrl+C stopped closing the overlay (fixed 2026-11-18).** The overlay's tag field was a `TextField` that always existed, hidden while no tag was being typed. Once it had taken the focus (T, or a click on "+ tag"), it stayed the key scope's focus item even when hidden, so every key went to it: Escape was handled by its own handler (it only closed the field) and Ctrl+C is "copy" in a text field, so neither reached the overlay's `Keys.onPressed`. Reproduced with QtTest key events in a scratch copy (`TestCase.keyClick` on a `TestCase { when: false }`, which sends keys straight to the window and so tests focus and handlers without the compositor; after T and Esc the field still reported `activeFocus` and the second Esc did nothing). Fix: the field is a `Loader` that exists only while `addingTag` is true (a destroyed field leaves the focus with the scope again). After the fix Esc and Ctrl+C close the overlay after T + Esc, after a typed tag, after clicking a chip and after cancelling. **General rule: never keep a hidden TextField (or another item that takes keys) in a scope whose own key handler matters; create it when needed.** A real arrow key through the compositor (`wtype -k Right`) did move the selection of the scratch overlay, so real keys reach it; a real Escape was not sent (blocked by the permission classifier after an earlier Escape interrupted the session). Also noted: `ps | grep` for scratch processes must not match the text of your own command (a pattern such as `[c]t/test.qml` still matches the `$S/ct/test.qml` that is in the command line and killed the calling shell, exit 144): use PID files.

**Picking an existing tag instead of typing it (both forms, 2026-11-18).** `WallpaperStore.suggestTags(known, have, typed, limit)` is the shared matching: the tags some wallpaper has that this one does not (the built-in `favourite` is left out), narrowed by the LAST comma-separated part of what is typed ("calm, wa" looks for "wa"), tags that start with it first, then the most used. **Overlay:** pressing T (or "+ tag") opens the field and puts a plate "existing" under it with the suggestions as segments (`SegmentChip.qml`, the same segmented look as the list filter; all of them at once, narrowing as you type, at most 7); click one, or Down / Up to highlight and Enter, or Tab for the highlighted one (else the first); picking keeps the field open for more, Enter with nothing highlighted adds what is typed as a new tag and closes the field, Esc cancels. Picking after "calm, wa" adds "calm" and the suggestion. **Window:** the suggestion chips under the pane's tag field use the same matching, and the field has the same Down / Up / Enter / Tab keys (the highlighted chip is drawn selected; clicking a chip adds it; the field stays focused). Checked with key events fed inside scratch copies (QtTest): all offered on T, narrowing, Tab, Down + Enter, the comma case, a new tag, Esc closing only the field, and the same keys in the window pane; screenshots of the overlay plate. NOT checked: clicking a suggestion, long tag lists (the plate clips at its width and shows at most 7), real keys through the compositor.

**Favourites, tags and the list filter (both forms, 2026-11-18).** `favourite` is a built-in tag (`WallpaperStore.favouriteTag`; `isFavourite`, `toggleFavourite`, `favouriteCount`): an ordinary tag in `wallpapers.json`, so the star and the tag filter agree. **Window form:** a star on every card (top left; shown for favourites and while the mouse is over the card), a star next to the name in the detail pane, **Ctrl+F** in the search field, and a pinned "★ Favourites n" chip first in the filter row (it is always there, even with none; the other tag chips follow, the `favourite` tag is left out of the tag chips and suggestions of the pane because the star says it). **Overlay:** the bar at the top of the screen picks which wallpapers are in the carousel: "★ Favourites n", "All n", then the other tags (Tab / Shift+Tab cycle, or click; one at a time). **It opens on the favourites if any wallpaper has the tag, otherwise on All** (decided each time it opens, once the files are known, so it also works if they are read after opening). The selection starts on the wallpaper that is on the screen if it is in the list, else on the first one; nothing is applied by opening or by changing the list, so when the middle picture is not the one on the desktop the subtitle says "not applied: Space" and the "Current" badge shows which one is. Space, a click on the middle picture or Enter (which also closes) applies it; scrolling applies as before. On the middle picture the top has the star (F, or a click) and the tags of the wallpaper as removable chips (a click on a chip lists that tag), and "+ tag" / T opens a text field (comma separated, Enter adds, Esc cancels; while it has the keys the overlay's own keys are off). Un-starring a wallpaper while the favourites are listed makes it leave the list at once (the selection stays on the same place). An empty list says so (no favourites yet: Tab for all, F on one you like). Checked (scratch copy, hooks, live session): no favourites -> All; favourites exist -> the list is the favourites (also when the desktop wallpaper is not one: "not applied", Space applies it); Tab cycles both ways; unfavouriting inside the favourites list; adding tags and listing by one; scroll-to-apply and colour stepping with wrap-around after the rewrite; screenshots of the overlay (filter bar, star, tag chips, the tag field) and of the window form (pinned chip, pane star); no warnings, no crash report. NOT checked: the keys themselves (Shift+arrows, Tab, F, T, Space, Enter: only the functions they call), clicking stars, chips and the tag field, the card stars' hover behaviour in the window, a long tag list in the bar, many wallpapers.
